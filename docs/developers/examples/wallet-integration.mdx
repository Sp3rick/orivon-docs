This example shows how a module works with the user's wallet: requesting the
permission, signing a message, and submitting a transaction. It is the shape
of every payment and authorization flow.

## Project structure

```text
wallet-integration/
  orivon.toml
  src/
    index.ts
```

## The manifest

The module needs two wallet capabilities:

```toml
[package]
name = "wallet-integration"
version = "0.1.0"
description = "Signs messages and sends transactions"

[interface]
methods = ["signMessage", "sendPayment"]

[permissions]
wallet = ["sign", "send"]
```

The `wallet` permissions cover signing and sending. They are requested
narrowly: this module can sign and send, and nothing else.

<Callout type="success" title="Principle">
  Request the narrowest permissions your feature needs. A review reads the
  manifest as a promise of what your code will do. See
  [Permissions](/docs/developers/permissions).
</Callout>

## The implementation

`src/index.ts` uses the wallet service:

```ts
export async function signMessage(input: {message: string}) {
  return app.wallet.sign(input.message, {from: input.account});
}

export async function sendPayment(input: {to: string; value: string}) {
  return app.wallet.send({to: input.to, value: input.value, data: '0x'});
}
```

The wallet prompts the user before signing or sending. Your module should
handle the user declining:

```ts
export async function sendPayment(input: {to: string; value: string}) {
  try {
    return await app.wallet.send({to: input.to, value: input.value, data: '0x'});
  } catch (error) {
    if (error.code === 'user_canceled') {
      return {status: 'canceled'};
    }
    throw error;
  }
}
```

## Running it

```sh
orivon build
orivon run --call wallet-integration signMessage '{"account":"alice","message":"hello"}'
```

The runtime routes the call to the wallet, the user confirms, and the
signature comes back in the response.

## What this example teaches

- Privileged operations live behind permissions and user confirmation.
- Wallet calls can fail with `user_canceled`; handle it.
- The module never holds keys; the wallet does.

Tutorials are guided paths that take you from a blank directory to a working
system. Unlike [examples](/docs/developers/examples), which show finished
projects, tutorials explain every step as they go, so you understand not just
what to type but why.

<Callout type="info" title="Who are the tutorials for?">
  Tutorials assume you have a working [development environment](/docs/developers/development-environment)
  and have done the [quick start](/docs/developers/quick-start) at least once.
  Each tutorial lists its prerequisites.
</Callout>

## How a tutorial is structured

Every tutorial shares a common shape, so you always know where you are:

<Steps>
  <Step title="Prerequisites">
    What you need before starting, and what you should have done.
  </Step>
  <Step title="Setup">
    Scaffolding the project and the manifest.
  </Step>
  <Step title="Core code">
    The main implementation, explained block by block.
  </Step>
  <Step title="Integration">
    Wiring permissions, events and configuration.
  </Step>
  <Step title="Run it">
    Building, running and exercising the result.
  </Step>
  <Step title="Extend">
    Suggested next steps and common variations.
  </Step>
</Steps>

## Suggested order

If you are new to the platform, follow this order. Each tutorial builds on
concepts from the previous ones:

<CheckList
  items={[
    'Building a wallet: the identity foundation.',
    'Using permissions: how authorization works.',
    'Working with events: how packages communicate.',
    'Creating a storage provider: your first service.',
    'Creating a DNS provider: your second service.',
    'Building a network provider: traffic in motion.',
  ]}
/>

<Callout type="success" title="Learn by building">
  The fastest route to fluency is to build all three providers, because they
  exercise the same architecture from different angles: manifest, permissions,
  configuration, events and the request cycle. After that, the whole platform
  feels like variations on one pattern.
</Callout>

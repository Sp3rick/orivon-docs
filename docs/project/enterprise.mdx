This page helps organizations evaluate Orivon for enterprise use. It covers
adoption considerations, deployment models, security posture, and the path
to production.

<Callout type="info" title="Enterprise program in development">
  Orivon's formal enterprise program (SLAs, dedicated support, professional
  services) is being designed for 2027 launch. This page describes the
  platform's enterprise-relevant capabilities as of v1.2.
</Callout>

## Why organizations evaluate Orivon

| Driver | Orivon Advantage |
| --- | --- |
| **Data sovereignty** | Local-first architecture; user/org controls data; no mandatory telemetry. |
| **Supply chain security** | Signed releases, SBOMs, SLSA Level 3 target, capability-based sandbox. |
| **Customization** | Module system enables policy enforcement, custom protocols, internal tooling. |
| **Standards compliance** | Open specifications; no vendor lock-in; interoperable by design. |
| **Auditability** | Open source; capability logs; deterministic builds; reproducible artifacts. |
| **Cost control** | No per-seat licensing; self-hosted infrastructure; community support. |

## Deployment models

| Model | Description | Control | Operational Burden | Best For |
| --- | --- | --- | --- | --- |
| **Self-hosted (full)** | Org runs browser, runtime, registry, identity | Maximum | High | Regulated, air-gapped, custom policy |
| **Self-hosted (registry only)** | Org runs module registry; uses upstream browser/runtime | High | Medium | Policy control, internal modules |
| **Managed (planned)** | Orivon partners operate infrastructure | Medium | Low | Teams wanting SaaS-like experience |
| **Hybrid** | Mix of above (e.g., cloud registry, local runtime) | Flexible | Variable | Gradual adoption, multi-region |

## Security for enterprise

| Capability | Status | Details |
| --- | --- | --- |
| **Capability-based sandbox** | ✅ v1.0 | Per-module, fine-grained, auditable |
| **Signed releases + SBOM** | ✅ v1.0 | Cosign/Sigstore, CycloneDX |
| **No telemetry by default** | ✅ v1.0 | Opt-in only, local-first |
| **Local data storage** | ✅ v1.0 | Encrypted, user-controlled |
| **DID-based identity** | ✅ v1.0 | Standards-based, portable |
| **Policy enforcement** | ✅ v1.2 | Capability allowlists, module signing |
| **FIPS 140-3 crypto** | Evaluating | aws-lc-rs uses FIPS modules |
| **Hardware isolation (TEE)** | Research | Planned for v2.0+ |

## Scalability

| Dimension | Current (v1.2) | Target (v2.0) |
| --- | --- | --- |
| **Concurrent modules** | 100s per browser | 1000s |
| **Module cold start** | < 500ms | < 100ms |
| **Module hot reload** | Design (v1.3) | < 50ms |
| **Registry scale** | 10k modules | 1M+ modules |
| **Identity operations** | 1k req/s | 100k req/s |
| **P2P nodes** | Experimental | Production mesh |

## Mission Statement

**To build an open-source browser and platform that returns control of the web
to its users — enabling user-owned identity, private data, and a programmable
web where participants are rewarded for the value they create.**

This mission drives every technical decision, governance choice, and community
interaction. It is the standard against which proposals, features, and
partnerships are measured.

## Vision Statement

> **A web where users control their data, identity, and attention. Where
> developers build without asking permission from a platform. Where
> participants are rewarded for the value they contribute. Where innovation
> happens in the open, under community governance.**

This vision describes the world we are building toward. It is ambitious,
long-term, and intentionally broader than any single product release.

## Long-term objectives

| Horizon | Objective | Success indicators |
| --- | --- | --- |
| **1–2 years** | **Platform maturity** — Stable runtime, browser, SDK, and standards v1. | Production-ready releases, growing contributor base, ecosystem projects. |
| **3–5 years** | **Ecosystem scale** — Self-sustaining module marketplace, global contributor network. | 1000+ ecosystem projects, 100+ active maintainers, regional communities worldwide. |
| **5–10 years** | **Web transformation** — Orivon capabilities adopted as web standards; user agency normalized. | Standards track at W3C/IETF, major platform integrations, measurable user adoption. |
| **10+ years** | **Permanent public good** — Independent foundation, perpetual sustainability, global impact. | Endowed foundation, multi-stakeholder governance, recognized steward of open web. |

## Strategic priorities

### 1. Technical excellence
- Capability-based security as a differentiator.
- WebAssembly performance leadership.
- Zero-trust architecture by default.
- Rigorous specification and conformance testing.

### 2. Open standards leadership
- Publish and maintain open specifications for all platform layers.
- Participate in W3C, IETF, TC39, and related standards bodies.
- Ensure specifications are implementable by others without Orivon dependency.

### 3. Community governance
- Meritocratic, transparent governance (Apache-style).
- Distributed leadership: maintainers, working groups, TSC.
- Clear paths from contributor to leader.

### 4. Ecosystem enablement
- SDKs, tooling, and documentation that make building on Orivon natural.
- Grants program funding infrastructure, research, and applications.
- Partner program for technology and integration partners.

### 5. Enterprise readiness
- Deployment models for organizational use.
- Security, compliance, and support frameworks.
- Professional services ecosystem.

### 6. Sustainable funding
- Diversified funding: sponsors, grants, professional services, ecosystem revenue.
- Transparent financial reporting.
- Legal structure (foundation) that protects the mission.

<Callout type="note" title="Metrics are indicators, not targets">
  These metrics help the community understand trajectory. They are not KPIs
  that drive behavior — the mission drives behavior. Metrics are reported
  quarterly in [Transparency Reports](/docs/project/transparency).
</Callout>

| Value | How it shapes strategy |
| --- | --- |
| **Transparency** | Public roadmaps, open meetings, published decisions. |
| **Meritocracy** | Influence follows contribution, not affiliation. |
| **User agency** | Features default to user control; opt-in for data sharing. |

| **Sustainability** | Funding and governance designed to outlast individuals. |

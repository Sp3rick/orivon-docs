## Repository organization

All code repositories live under the `OrivonBrowser` GitHub organization (or
equivalent). The repository topology:

<CardGrid columns={2}>
  <Card title="Core Platform" to="https://github.com/OrivonBrowser">

    <strong>orivon-browser</strong> — Browser application, rendering, UI<br/>
    <strong>orivon-core</strong> — Shared libraries: networking, storage, identity, permissions<br/>
    <strong>orivon-modules</strong> — Official module registry and standard modules

## Documentation structure

This documentation site (`orivon-docs`) is organized into **levels** — each a
major section with its own navigation group:

| Level | Directory | Status | Description |
| --- | --- | --- | --- |
| 1 | `introduction/` | Live | What is Orivon, why it exists, vision, architecture overview |
| 2 | `ecosystem/` | Live | Browser, runtime, core, modules, SDK, wallet, identity, naming, Web3 Score, security, networking, storage, governance |
| 3 | `technical-design/` | Live | Architecture, browser/runtime/core/module architecture, core systems, platform, internals |
| 4 | `standards/` | Live | Overview, authoring, registry, compliance, roadmap |
| 5 | `api-reference/` | Live | All APIs: runtime, core, browser, module, application, wallet, identity, storage, networking, DNS, permissions, security, events, interfaces, classes, functions, methods, objects, enums, types, formats, status, tooling, resources |
| 6 | `research/` | Live | 39 publications: whitepapers, design docs, architecture papers, research areas, future tech, experimental |
| 7 | `community/` | Live | 39 pages: overview, mission, community, governance, maintainers, WGs, TSC, decision-making, roadmaps, philosophy, recognition, showcase, events, meetups, hackathons, grants, sponsors, partners, ecosystem, media, brand, social, newsletter, FAQ |
| 8 | `project/` | Live | **This level** — Organization, leadership, core team, maintainers, advisors, structure, releases, trust, compliance, enterprise, support, partnerships, funding, brand, resources |
| 9 | `developers/` | Live | Getting started, setup, guides, APIs, platform, engineering, resources |
| 10 | `contributors/` | Live | Overview, getting started, community, contributing, quality, security, resources |

## Standards organization

Standards are maintained in the `orivon-standards` repository and published
to this site under the **Standards & Specifications** level.

| Standard | Repository | Status | Spec Level |
| --- | --- | --- | --- |
| Module Format | `orivon-standards` | Accepted v1.0 | Core |
| Capability Model | `orivon-standards` | Accepted v1.0 | Core |
| Naming System | `orivon-standards` | Accepted v1.0 | Core |
| Identity (DID) | `orivon-standards` | Accepted v1.0 | Core |
| Web3 Score | `orivon-standards` | Accepted v1.0 | Feature |
| Security Model | `orivon-standards` | Accepted v1.0 | Core |
| Networking Protocols | `orivon-standards` | Draft v0.9 | Platform |
| Storage Protocols | `orivon-standards` | Draft v0.9 | Platform |

See [Specification Registry](/docs/standards/specification-registry) for the
authoritative list with versions and links.

## SDK organization

| SDK | Repository | Language | Status |
| --- | --- | --- | --- |
| **orivon-sdk-ts** | `orivon-sdk-ts` | TypeScript | v1.x stable |
| **orivon-sdk-rs** | `orivon-sdk-rs` | Rust | v1.x stable |
| **orivon-cli** | `orivon-cli` | TypeScript/Rust | v1.x stable |

SDKs are versioned independently but aligned with platform releases. See
[API Reference](/docs/api-reference/overview) for the generated API docs.

## Supporting projects

| Project | Purpose | Repository |
| --- | --- | --- |
| **Package Registry** | Module discovery, publishing, resolution | `orivon-registry` |
| **Documentation Site** | This site (Astro + React + MDX) | `orivon-docs` |
| **Community Forum** | Discussions, RFCs, governance | `orivon-forum` (Discourse) |
| **Chat** | Real-time coordination | Discord (managed) |
| **CI/CD** | Build, test, release automation | `orivon-ci`, `orivon-release` |
| **Monitoring** | Observability, alerting, status page | `orivon-infra` |

## Cross-cutting concerns

| Concern | Owner | Implementation |
| --- | --- | --- |
| **Security** | Security WG + Area Maintainer | Threat models, audits, disclosure, crypto review |
| **Accessibility** | Accessibility Maintainer | WCAG 2.1 AA compliance, browser + docs |
| **Internationalization** | Translation Leads | Docs + UI localization (planned) |
| **Performance** | Runtime + Browser Teams | Benchmarks in CI, regression detection |
| **Supply Chain** | Infrastructure Team | Dependency scanning, SBOM, signing, provenance |
| **Documentation** | Documentation WG | Site, guides, API reference, research library |

## Getting the code

```bash
# Clone the main platform repositories
gh repo clone OrivonBrowser/orivon-runtime
gh repo clone OrivonBrowser/orivon-browser
gh repo clone OrivonBrowser/orivon-core
gh repo clone OrivonBrowser/orivon-sdk-ts

# Or clone the monorepo starter (if available)
gh repo clone OrivonBrowser/orivon-monorepo
```

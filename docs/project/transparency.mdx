Quarterly transparency reports provide the community, sponsors, and stakeholders
with a clear view of Orivon's financial health, operational metrics, governance
activity, and progress toward sustainability.

## Report template

Each report contains:

### 1. Executive Summary (1 page)
- Key metrics dashboard.
- Major achievements.
- Top risks/concerns.
- Outlook for next quarter.

### 2. Financials
| Section | Content |
| :--- | :--- |
| **Revenue** | By source (sponsors, grants, services, other) |
| **Expenses** | By category (infra, security, grants, community, docs, ops, reserves) |
| **Cash Position** | Opening, closing, runway (months) |
| **Reserves** | Emergency fund, endowment progress |
| **Grant Disbursements** | By cycle, category, recipient |
| **Sponsor Contributions** | By tier (anonymized if requested) |

### 3. Operational Metrics
| Area | Metrics |
| :--- | :--- |
| **Platform** | Releases, downloads, registry modules, active versions |
| **Community** | Contributors (30d), maintainers, WG activity, events |
| **Ecosystem** | Projects listed, grants awarded, partners, integrations |
| **Infrastructure** | Uptime, latency, error budgets, incidents |
| **Security** | Advisories, disclosures, audit status, bug bounty |
| **Documentation** | Pages, translations, search queries, feedback |

### 4. Governance
| Area | Metrics |
| :--- | :--- |
| **TSC** | Meetings, decisions, votes, elections |
| **Working Groups** | Charters, meetings, outputs, recommendations |
| **Maintainers** | Appointments, emeritus, scope changes |
| **Decisions** | Proposals submitted/accepted/rejected/deferred |
| **Code of Conduct** | Incidents, resolutions (anonymized) |

### 5. Risk & Compliance
| Area | Content |
| :--- | :--- |
| **Top Risks** | Likelihood × impact, mitigation status |
| **Compliance** | Certification progress, audit findings, gaps |
| **Legal** | Trademarks, contracts, disputes (high-level) |
| **Security** | Open advisories, supply chain incidents |

### 6. Outlook
- Next quarter priorities.
- Upcoming milestones.
- Resource needs.
- Community asks.

## Machine-readable data

Each report includes:
- **`metrics.json`** — Structured data for dashboards/analysis.
- **`financials.csv`** — Line-item revenue/expenses (redacted for privacy).
- **Schema versioning** — `metrics-schema.json` for compatibility.

Example `metrics.json`:
```json
{
  "period": "2026-Q3",
  "generated": "2026-10-10T12:00:00Z",
  "schemaVersion": "1.0",
  "financials": {
    "revenue": {"sponsors": 150000, "grants": 75000, "services": 0},
    "expenses": {"infrastructure": 25000, "security": 18000, "grants": 60000, "community": 12000, "documentation": 8000, "operations": 15000},
    "cashPosition": {"opening": 200000, "closing": 305000, "runwayMonths": 18}
  },

    "contributors30d": 120,
    "maintainers": 25,

  "platform": {
    "releases": 3,

    "registryModules": 120,
    "activeVersions": 3
  }
}
```

## Publication process

<Steps>
  <Step title="Data collection">
    Finance, infra, community, security leads compile metrics (weeks 1–2 post-quarter).
  </Step>
  <Step title="Draft">
    Transparency lead authors report using template (weeks 2–3).
  </Step>
  <Step title="Review">
    TSC + Foundation (when formed) review for accuracy, completeness (week 4).
  </Step>
  <Step title="Publish">
    Report + data files committed to `orivon-transparency` repo; announced via newsletter, blog, social.
  </Step>
  <Step title="Discussion">
    Forum thread for community questions (2 weeks).
  </Step>
</Steps>

dependencies. It is **generated automatically** from `Cargo.lock`,
`package-lock.json`, and other lockfiles at each release.

## Dependency policy enforcement

| Rule | Enforcement |
| --- | --- |
| **No copyleft** | `cargo deny check licenses` — blocks GPL, AGPL, LGPL, etc. |
| **Permissive only** | Allowlist: Apache-2.0, MIT, BSD-*, ISC, CC0, Unicode-DFS-2016, MPL-2.0 (review), EPL-2.0 (review) |
| **License file required** | Every dependency must have a license file or SPDX header |
| **SPDX in lockfile** | `cargo metadata --format-version=1` includes license data |
| **Audit trail** | `THIRD-PARTY-LICENSES.json` published with every release |

## Generating the registry

The registry is generated during release:

```bash
# Cargo dependencies
cargo metadata --format-version=1 > cargo-metadata.json
cargo-license --json > cargo-licenses.json

# npm dependencies
npm ls --json --all > npm-deps.json
license-checker --json > npm-licenses.json

# Combine and deduplicate
./scripts/generate-third-party-licenses.js \
  --cargo cargo-licenses.json \
  --npm npm-licenses.json \
  --output THIRD-PARTY-LICENSES.json
```

## Verification

Users can verify the registry against the release:

```bash
# Download release artifacts
wget https://github.com/OrivonBrowser/orivon-runtime/releases/download/v1.2.0/THIRD-PARTY-LICENSES.json

# Verify against lockfile
./scripts/verify-licenses.sh THIRD-PARTY-LICENSES.json Cargo.lock package-lock.json
```

## Exception process

If a critical dependency has a non-permissive license:

1. **Document** — File an issue with justification and alternatives analysis.
2. **Review** — Security WG + Legal (when Foundation formed) review.
3. **Approve** — TSC supermajority vote required.
4. **Mitigate** — Isolate in separate process/module; plan migration.
5. **Track** — Exception logged in `THIRD-PARTY-LICENSES.json` with `exception: true`.

**Current exceptions:** None.

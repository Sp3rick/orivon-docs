The Orivon roadmap communicates the project's direction across three
horizons. It is a living document updated each release cycle by the TSC with
community input. The roadmap reflects **intent**, not commitment — dates are
targets, not promises.

<Callout type="info" title="Roadmap vs. Release Lifecycle">
  The [Release Lifecycle](/docs/project/release-lifecycle) defines *when* and
  *how* releases ship. The **Roadmap** defines *what* we aim to build and
  *why*. They are aligned but distinct.
</Callout>

## Roadmap principles

| Principle | Practice |
| --- | --- |
| **Community-shaped** | Priorities discussed in open forums; anyone can propose work. |
| **Evidence-based** | Decisions driven by user feedback, benchmarks, security research. |
| **Transparent** | Roadmap public; progress reported in release notes and TSC minutes. |
| **Flexible** | Scope adjusts based on learning; dates shift for quality. |
| **Sustainable** | Workload balanced; contributor health prioritized over velocity. |

## Mid-term goals (2027 – 2028)

### Ecosystem scale
- **Module marketplace** — Discoverable, reviewed, signed modules with ratings.
- **Package registry v2** — Namespaces, scoped packages, provenance, SBOM.
- **CI/CD templates** — GitHub Actions, GitLab CI, Azure Pipelines for Orivon projects.
- **Enterprise support tier 1** — SLA-backed support for LTS releases.
- **Regional community leads** — Stipended organizers in 25+ regions.

### Identity & privacy
- **DID method registration** — Multiple DID methods (web, key, ion, custom).
- **Verifiable credential flows** — Issuance, presentation, verification in browser.
- **Private compute** — TEE integration, secure enclaves for sensitive modules.
- **Zero-knowledge proofs** — ZK-SNARK/STARK support for privacy-preserving apps.

### Networking
- **P2P transport** — libp2p integration, hole punching, relay mesh.
- **Latency optimization** — QUIC tuning, connection pooling, predictive fetch.
- **Decentralized DNS** — Full naming system deployment, dispute resolution v2.
- **Content addressing** — IPFS/CID integration for module distribution.

### AI integration
- **Local inference** — WASM-NN, WebGPU compute for on-device ML.
- **Agent protocols** — Standardized agent communication, capability delegation.
- **Privacy-preserving ML** — Federated learning, differential privacy primitives.

## Long-term vision (2028+)

### User-owned web
| Pillar | Description |
| --- | --- |
| **Sovereign identity** | Every user controls their DID, keys, and credentials — no platform intermediary. |
| **Personal data vault** | Local-first encrypted storage; user decides what leaves their device. |
| **Attention economy** | Users opt into value exchange; Web3 Score rewards contribution, not extraction. |
| **Algorithmic choice** | Feed ranking, content filtering, search — user-selectable, auditable. |

### Programmable value
| Pillar | Description |
| --- | --- |
| **Module economy** | Developers publish modules; users/institutions sponsor; revenue flows to creators. |
| **Reputation portability** | Web3 Score moves across apps; no walled-garden reputation. |
| **Micro-grants** | Automated, community-governed funding for high-impact contributions. |
| **DAO tooling** | Native governance modules for decentralized organizations. |

### Decentralized infrastructure
| Pillar | Description |
| --- | --- |
| **User-operated nodes** | Browser runs on a mesh of user devices; no central servers required. |
| **Resilient naming** | Naming system survives single points of failure; censorship-resistant. |
| **Distributed storage** | Data replicated across user nodes; privacy-preserving, incentive-aligned. |
| **Edge compute** | Modules execute near users; latency minimized, bandwidth reduced. |

### Open standards by default
| Pillar | Description |
| --- | --- |
| **Standards track** | All platform protocols submitted to W3C/IETF/TC39. |
| **Multiple implementations** | Reference + independent implementations for every standard. |
| **Conformance suites** | Automated test suites ensuring interoperability. |
| **Patent commitments** | Royalty-free licensing for all standard-essential patents. |

## How the roadmap is set

<Steps>
  <Step title="Community input">
    Forum discussions, working group backlogs, contributor surveys, user feedback.
  </Step>
  <Step title="Working group proposals">
    Each WG proposes priorities for their domain with evidence and estimates.
  </Step>
  <Step title="TSC synthesis">
    TSC integrates proposals, resolves conflicts, aligns with capacity and strategy.
  </Step>
  <Step title="Public review">
    Draft roadmap published for 14-day community comment.
  </Step>
  <Step title="Ratification">
    TSC ratifies final roadmap; published with release notes.
  </Step>
  <Step title="Quarterly review">
    Progress assessed; adjustments made; communicated in newsletter.
  </Step>
</Steps>

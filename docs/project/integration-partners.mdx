Integration Partners connect **external systems to the Orivon ecosystem** —
bridging protocols, identity systems, payment networks, storage layers, and
standards bodies.

<Callout type="info" title="Coming Soon">
  No integration partners have been formally announced as of July 2026. This
  page is reserved for future partnerships.
</Callout>

## Integration partner profile

| Attribute | Description |
| :--- | :--- |
| **Integration direction** | External system to Orivon (or bidirectional) |
| **Types** | Blockchain bridges, identity providers, storage backends, payment rails, standards bodies |
| **Value to partner** | Access to Orivon user base, module ecosystem, Web3 Score |
| **Value to Orivon** | Expanded capabilities, interoperability, ecosystem growth |

## Integration categories (planned)

| Category | Examples | Orivon Touchpoint |
| :--- | :--- | :--- |
| **Blockchain Bridges** | Ethereum, Solana, Polkadot, Cosmos, Bitcoin | Module + Naming System |
| **Identity Providers** | DID methods (ion, web, key, peer), Verifiable Credential issuers | Identity Layer |
| **Storage Backends** | IPFS, Filecoin, Arweave, Storj, S3-compatible | Storage Engine |
| **Payment Rails** | Stripe, crypto payments, stablecoin rails | Wallet System, Web3 Score |
| **Standards Bodies** | W3C, IETF, TC39, Decentralized Identity Foundation | Standards Process |
| **AI/ML Providers** | Local inference (llama.cpp, ONNX), privacy-preserving ML | Runtime (WASM-NN) |
| **Hardware Vendors** | TEE/SGX/SEV providers, secure element manufacturers | Runtime Sandbox |

## Integration requirements

| Requirement | Details |
| :--- | :--- |
| **Standards-based** | Use Orivon published specs (Module Format, Capability Model, Naming, Identity) |
| **Open specification** | Integration spec published (or commit to publish) |
| **Conformance testing** | Pass Orivon conformance suite (when available) |
| **Security review** | Threat model + Orivon Security WG review |
| **Maintenance commitment** | Track Orivon releases; update within 30 days of breaking changes |
| **Public documentation** | Integration guide in Orivon docs or partner site |

## Benefits for integration partners

| Benefit | Details |
| :--- | :--- |
| **Standards collaboration** | Joint work on W3C/IETF specs; shared test suites |
| **Early spec access** | Review drafts before publication |
| **Conformance program** | "Orivon Compatible" badge (planned) |
| **Co-marketing** | Joint announcements, case studies, webinars |
| **Grants priority** | Integration work eligible for Grants Program |
| **Technical liaison** | Named Orivon engineer for integration support |

## How to propose an integration

**Email:** partnerships@orivon.dev

Include:
- External system description and user base.
- Integration architecture (diagram preferred).
- Orivon touchpoints (which specs, APIs, layers).
- Conformance approach.
- Maintenance plan.
- Mutual value hypothesis.

## Integration lifecycle

<Steps>
  <Step title="Propose">
    Submit integration proposal via email or forum RFC.
  </Step>
  <Step title="Review">
    Technical review by relevant Working Group + Security WG.
  </Step>
  <Step title="Prototype">
    Build proof-of-concept; run conformance tests.
  </Step>
  <Step title="Standardize">
    Publish integration spec; contribute to conformance suite.
  </Step>
  <Step title="Announce">
    Joint announcement; partner directory listing.
  </Step>
  <Step title="Maintain">
    Track Orivon releases; update integration; participate in security.
  </Step>
</Steps>

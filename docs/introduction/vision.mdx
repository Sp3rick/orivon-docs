## Where this is heading

The vision for Orivon is deliberately ambitious: a web that works the way it was always
meant to: open, decentralized, and owned by its users. This page describes where the
project is heading over the long term and the shifts that make it possible.

## The future ecosystem

Orivon is not just a browser. It is a platform with several connected layers:

| Layer | Role in the ecosystem |
| --- | --- |
| **Standards** | Public specifications that define how everything interoperates. |
| **Core** | The neutral foundation every implementation shares. |
| **Runtime** | Executes applications consistently across devices. |
| **Browser** | The interface users actually experience. |
| **Modules** | Community-built capabilities such as wallets, DNS, storage and identity. |
| **Applications** | The software of the future web, distributed as websites. |

<Callout type="success" title="The key idea">
  Every layer is a standard, not a product. Orivon provides a reference implementation,
  and everyone is free to build on the same foundation.
</Callout>

## How Orivon changes software distribution

Today, software is distributed through app stores and installers controlled by platforms.
The Orivon model treats **applications as websites**:

- No installation step. You visit and it runs.
- Updates happen the moment you open the app, so it is always current.
- No gatekeeper takes a cut of every transaction.
- Distribution is as open as the web itself.

The browser becomes the operating environment, and the web becomes an app store that
nobody owns.

## How applications become websites

For an application to truly run like a website, the browser needs a capable runtime:

```text
Application (HTML / CSS / JS / WASM)
        │
        ▼
Orivon Runtime  ─── runs the app
        │
        ▼
Orivon Core  ────── provides services: identity, value, storage, DNS
        │
        ▼
Open Standards  ── everything interoperates
```

The runtime is the piece that makes applications behave like native software. It provides
secure storage, permissions, and access to decentralized services, while staying as
portable as a URL.

## How decentralized computing evolves

As applications move to the browser, computing itself becomes decentralized:

- **Storage** moves to user-controlled networks instead of corporate data centers.
- **Identity** becomes a public key owned by the user, not a login owned by a platform.
- **Value** flows directly between peers instead of through intermediaries.
- **Compute** can be distributed across networks that no single entity controls.

None of this requires abandoning the web. It requires the web's own tools to evolve: the
browser and its standards. That is the work Orivon is doing.

## Guiding principles for the long term

1. **Openness over ownership.** Standards are public; governance is community-driven.
2. **User control over platform control.** Keys, data and decisions belong to users.
3. **Compatibility over disruption.** Evolve the web platform; don't fracture it.
4. **Simplicity over complexity.** Powerful capabilities, understandable interfaces.

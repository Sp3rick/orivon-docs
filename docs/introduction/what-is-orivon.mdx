## The short answer

Orivon is an open, community-driven **browser for Web3**. It is designed to make
decentralized technologies such as wallets, tokens, identities, storage and dApps as natural
to use as opening a webpage. It is built on **new open standards** rather than closed,
proprietary platforms.

It is a browser, a runtime, and a foundation for a future ecosystem. All of it is defined in
the open and specified here in this documentation.

## Core philosophy

Orivon's philosophy can be summarized in a few principles:

| Principle | Meaning |
| --- | --- |
| **Trustless by default** | The browser verifies what it shows you. No hidden intermediaries, no opaque third parties. |
| **User sovereignty** | Your keys, your data and your identity are owned and controlled by you. |
| **Open standards** | Every capability is a public specification that anyone can implement, improve or extend. |
| **Modularity** | Features are modules that plug into a core, not a monolith owned by one company. |
| **Backward compatibility** | The existing web platform is not discarded; it is extended carefully without breaking what works. |

<Callout type="note" title="A browser, not a replacement for the web">
  Orivon does not reject the web. It builds on the classic Web platform (HTML, CSS,
  JavaScript, WebAssembly and the DOM) and adds the capabilities Web3 needs to work
  properly, while keeping backward compatibility.
</Callout>

## Main goals

Orivon exists to achieve a small set of concrete goals:

1. **Bring Web3 to mass adoption.** Reduce friction until decentralized apps are as easy to
   use as websites.
2. **Define open standards for Web3 browsing.** A public, neutral specification that other
   browsers and tools can adopt.
3. **Make security understandable.** Sandboxing, permissioning and a Web3 Score that help
   users make safe decisions without being security experts.
4. **Support a modular ecosystem.** Let the community build modules such as wallets, DNS,
   storage and identity without forking the browser.
5. **Protect user privacy.** No telemetry-by-default, no data harvesting, no surveillance
   business model.

## Who it is for

- **Everyday users** who want the benefits of Web3 without the technical hurdles.
- **Developers** who want a stable, documented platform to build decentralized applications.
- **Researchers** interested in new standards for identity, storage and distributed systems.
- **Investors** evaluating the future of the web infrastructure layer.
- **Contributors** who want to shape an open, community-owned project.

## How it differs from traditional browsers

<Diagram caption="Traditional browsers treat Web3 as an afterthought; Orivon places it at the center.">
  <Flow>
    <DiagramNode accent>Orivon Browser</DiagramNode>
    <FlowArrow />
    <DiagramNode>Web3 native</DiagramNode>
  </Flow>
</Diagram>

| Aspect | Traditional Browser | Orivon Browser |
| --- | --- | --- |
| Wallets | External extension, fragmented | First-class, built-in capability |
| Decentralized names | No native support | Native decentralized DNS |
| dApps | Manual, error-prone | Automatic, sandboxed, verified |
| Security model | Plugin-dependent | Built-in sandboxing + Web3 Score |
| Data & identity | Platform-owned | User-owned |
| Extensions | Often closed or ad-driven | Open module system |
| Standards | Vendor-defined | Community-defined open specs |

## Future vision

Over time, Orivon grows into a complete environment for the next generation of the web:

- applications that ship and update like websites,
- a runtime that runs them consistently across devices,
- networks that connect users directly, without intermediaries,
- and a foundation that keeps it all open and community-governed.

The path to that future is described in the [Vision](/docs/introduction/vision) and
[Roadmap](/docs/introduction/roadmap) pages.

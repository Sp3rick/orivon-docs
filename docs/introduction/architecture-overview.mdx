The architecture is designed around a simple idea: a **neutral core**, a **runtime** that
executes applications, a **browser** that presents them, and **modules** that extend the
whole, all grounded in **open standards**. This page maps the layers and how they relate.

## Layer by layer

### Standards

The bottom layer is **not code**. It is specifications. Standards define how objects,
identities, transactions, modules and the runtime behave, so that any implementation
interoperates with any other. Standards make the ecosystem open.

### Core

The **Core** provides the fundamental services every implementation needs: identity,
value, storage and connectivity. It is deliberately small, neutral and shared so that
different browsers and runtimes speak the same language.

### Runtime

The **Runtime** executes applications, including the existing web stack (HTML, CSS,
JavaScript, WebAssembly) plus the new capabilities defined by the standards. It is what
makes applications behave like software while remaining as portable as a URL.

### Browser

The **Browser** is the user-facing layer. It builds on the classic web platform and adds
Web3 capabilities natively: wallets, decentralized DNS, sandboxing and the Web3 Score. It
is where security, privacy and usability meet.

which means they can be built and distributed by anyone without forking the browser.

## Applications and networks

Applications run on the runtime and reach users through the browser. Networks such as
chains, storage systems and identity providers connect through the same core services, so
users interact with any network through a single, consistent interface.

## Design rules

The architecture follows a few rules that keep it consistent and scalable:

1. **Separation of concerns.** Standards define; the core provides; the runtime executes;
   the browser presents; modules extend.
2. **Interfaces over implementations.** Components talk through public interfaces, so any
   piece can be replaced.
3. **Backward compatibility.** The existing web platform is preserved and extended, never
   broken.
4. **One definition of truth.** Capabilities are specified once, in the standards, and
   referenced everywhere else.

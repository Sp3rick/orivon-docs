Events are the asynchronous notification mechanism of the platform. A package
subscribes with `app.on(event, listener)` (see [Runtime API](/docs/api-reference/runtime-api))
and receives a structured payload every time the event fires.

**Introduced:** 1.0 · **Status:** Stable

## Conventions

- Event names are namespaced strings: `domain:action`, lowercase, for example
  `wallet:balance-changed`.
- All event payloads are JSON-serializable.
- Events are delivered in order per domain; there is no cross-domain ordering
  guarantee.
- Listeners run sequentially; an `async` listener does not block later
  listeners but its rejection is reported via `module:error`.
- Events never carry secrets. Token material is not present in any payload.

## Subscribing

```ts
const off = app.on('wallet:balance-changed', (event) => {
  console.log(event.accountId, event.asset, event.amount);
});

// one-shot subscription
app.once('ready', () => app.log.info('started'));
```

Unsubscribing with the returned function is the only supported way to remove a
listener reliably across releases.

## Event registry

### Runtime and lifecycle

| Event | Payload | Trigger |
| --- | --- | --- |
| `ready` | `{}` | `activate()` resolved. |
| `activated` | `{startReason}` | Package became active. |
| `deactivated` | `{reason}` | Package was deactivated. |
| `message` | `MessageEnvelope` | Inbound message delivered. |
| `module:error` | `{id, error}` | Uncaught error reported. |

### Core and modules

| Event | Payload | Trigger |
| --- | --- | --- |
| `module:loaded` | `ModuleInfo` | Module loaded. |
| `module:unloaded` | `{id}` | Module unloaded. |
| `module:activated` | `ModuleInfo` | Module became active. |
| `module:deactivated` | `{id, reason}` | Module left active state. |
| `module:state-changed` | `ModuleInfo` | Lifecycle state changed. |
| `core:low-memory` | `MemoryUsage` | Memory pressure threshold crossed. |

### Browser

| --- | --- | --- |

| `tab:updated` | `Tab` | Tab URL/title changed. |

## Lifecycle

Events follow the lifecycle of the emitting object:

1. The emitting facade is constructed and its grants are installed.
2. Events are emitted only while the package is active.
3. After `deactivate()` resolves, no further events are emitted and all
   listeners are removed.

<Note title="Subscription timing">
  Subscribing before `activate()` is valid and recommended for setup that must
  not miss early events, such as `ready`. Events emitted during `activate()`
  are delivered after the subscribe calls made before it.
</Note>

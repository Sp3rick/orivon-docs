The Orivon ecosystem is more than a browser. It is the full set of products,
open standards and participants that work together so that users, not
platforms, own the web. This page is the map: what exists today, what is being
built, and how every piece connects.

## What the ecosystem is

An ecosystem is everything that must exist for the vision to hold together. In
Orivon's case that means four things working at once:

1. **Products** that people actually use, starting with the browser.
2. **Standards** that define how identities, value, data and modules behave,
   so that any implementation interoperates with any other.
3. **Infrastructure** such as decentralized naming, storage and networking that
   replaces the servers and gatekeepers of today's web.
4. **Participants** including developers, creators, validators and users who
   keep the ecosystem running and growing.

Each layer answers a single question:

- The **browser** answers "how do I get to the web?"
- The **runtime** answers "how do applications actually run?"
- The **core** answers "what shared services does everything need?"
- The **standards** answer "how do we all agree on what the web means?"

## Who participates

A healthy ecosystem needs more than code. It needs people playing different
roles:

<CardGrid columns={2}>
  <Card title="Users">
    Browse, own their identity and data, and choose which applications and
    modules to trust.
  </Card>
  <Card title="Developers">
    Build applications, modules and services against open standards, with no
    permission required.
  </Card>
  <Card title="Creators">
    Publish content and applications directly, without paying a platform for
    the right to reach an audience.
  </Card>
  <Card title="Network participants">
    Run infrastructure: storage, naming, and network relays that keep the
    ecosystem available and censorship resistant.
  </Card>
  <Card title="Validators and curators">
    Help compute signals like the Web3 Score and participate in governance.
  </Card>
  <Card title="Governance participants">
    Shape the standards through an open process, so the rules evolve with the
    community.
  </Card>
</CardGrid>

## How the pieces connect

Everything hangs together through interfaces defined by the standards. Wallets,
naming, storage and modules do not talk to a specific browser. They talk to the
core, through public interfaces, which means any of them can be replaced.

## The rules that hold it together

The ecosystem follows a small set of rules. They are worth remembering because
every design decision on the following pages is a consequence of them:

1. **Open standards first.** Interoperability comes from agreement, not from a
   single company owning the stack.
2. **Neutral core.** The shared services stay small and neutral so no single
   participant can capture them.
3. **Replaceable parts.** Any product can be swapped for a better one without
   breaking the rest.
4. **Backward compatibility.** The existing web keeps working; the ecosystem
   extends it instead of breaking it.

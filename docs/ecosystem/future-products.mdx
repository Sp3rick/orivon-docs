This page is different from the rest of the section. Everything here is
**planned**: a concept under design, not a shipped product. Nothing on this page
exists yet. It is published so that contributors, investors and curious readers
can see where the ecosystem is heading and shape that direction.

<Callout type="note" title="How to read this page">
  Every product below carries a <Badge variant="soon">Planned</Badge> badge. A
  planned product has a design direction but no release date. If you are
  evaluating the ecosystem, treat this page as a roadmap, not a specification.
</Callout>

## Closer looks

### Developer Hub

A single, welcoming place for developers: documentation, tutorials, sample
projects and community events. The Hub would complement this site, which
documents the ecosystem, and the [SDK](/docs/ecosystem/sdk), which provides the
tooling.

<Badge variant="soon">Planned</Badge>

### Module Marketplace

The [Modules](/docs/ecosystem/modules) page describes how modules are built,
signed and distributed. The Marketplace would add a discovery surface on top of
that model: search, reviews and curated collections, while keeping the
foundation open so no one is forced to use it.

<Badge variant="soon">Planned</Badge>

### Desktop and Cloud Runtimes

Today the [Runtime](/docs/ecosystem/runtime) ships inside the browser. The
Desktop Runtime would run applications as standalone programs, and the Cloud
Runtime would run them remotely so a lightweight device could stream a full
application. Both extend the same runtime, which keeps portability intact.

<Badge variant="soon">Planned</Badge>

### Enterprise products

The Enterprise Platform, Developer Portal and Management Console target teams
and organizations. They would provide the administration, compliance and
management surfaces that the core ecosystem deliberately leaves neutral.

<Badge variant="soon">Planned</Badge>

### Research Platform

Because the ecosystem is decentralized, understanding it needs dedicated
tooling: network measurements, safety research and user studies. The Research
Platform would support the community's ability to study its own web.

<Badge variant="soon">Planned</Badge>

## What is not planned

Equally important is what the ecosystem has no plans to become:

<CardGrid columns={2}>
  <Card title="A closed platform">
    The ecosystem will not lock users into a single browser or app store.
  </Card>
  <Card title="A surveillance business">
    The products are designed around user ownership, not data collection.
  </Card>
  <Card title="A content gatekeeper">
    Neutral infrastructure stays neutral; rules stay with communities through
    governance.
  </Card>
</CardGrid>

## How plans become products

Planned products move forward the same way everything else does: through the
[Governance](/docs/ecosystem/governance) process. A concept is proposed,
designed in the open, and built by whoever steps up. That means the products on
this page are not promises. They are opportunities.

  You can change this roadmap. The concepts on this page are shaped by
  contributors, and the standards process is open to proposals. See

</Callout>

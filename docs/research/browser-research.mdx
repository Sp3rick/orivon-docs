*Orivon Research Group · Browser Engineering · Status: Active Research*

This area studies the browser's past, its present limitations, and where it
must go next. The [Browser Architecture](/docs/research/browser-architecture)
paper describes the current design; this page records the research agenda.

## Browser evolution

### History and lessons

| Era | Lesson |
| --- | --- |
| Document web | Browsers were readers first. |
| Web applications | Browsers became runtimes. |
| Mobile web | Performance and power became existential. |
| Platform web | Browsers mediate identity, payments, and data. |

The conclusion: browsers are no longer document viewers or even application
runtimes — they are the platform layer of the digital economy.

## Modern browser limitations

| Limitation | Impact | Orivon direction |
| --- | --- | --- |
| No user identity | Sites reinvent login; identity rented. | Native identity surface. |
| No native payments | Extensions and redirects. | Native wallet. |
| Ad-driven economics | Tracking by design. | User-owned data model. |
| Opaque permissions | Users cannot audit site power. | Permission panel. |
| Centralized web dependency | CDNs, DNS, registrars. | Decentralized alternatives. |

### Research questions

- How do users perceive signing and identity UI?
- What default permission posture maximizes both safety and adoption?
- How should decentralized resources appear in the address bar?

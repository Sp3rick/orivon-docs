The project roadmap tracks what the engineering teams and community are
building, when it is expected, and how it connects to the long-term vision.
It is a living document updated each release cycle.

## Roadmap philosophy

- **Timeboxes, not dates.** We commit to scope within a release window, not to
  calendar dates. Quality and security come first.
- **Public and accountable.** The roadmap is public; progress is reported in
  release notes and TSC minutes.
- **Community-shaped.** Priorities are discussed in the open; anyone can
  propose work through the [decision process](/docs/community/decision-making).

<Callout type="info" title="Roadmap vs. Research Roadmap">
  This page covers the *product* roadmap: features, releases, and platform
  capabilities. The [Research Roadmap](/docs/research/research-roadmap) covers
  the long-form research program and exploratory work.
</Callout>

## Release trains

Orivon releases on a regular cadence with three tracks:

| Track | Cadence | Purpose |
| --- | --- | --- |
| **Stable** | Every 8–12 weeks | Production-ready releases with full QA. |
| **Beta** | Every 2–4 weeks | Feature-complete previews for testing. |
| **Nightly** | Continuous | Latest changes for early adopters and CI. |

Release notes for every version are published in the
[API Reference Changelog](/docs/api-reference/changelog).

## Future vision (post v2.0)

The long-term vision guides the roadmap but is not a commitment:

<CardGrid columns={2}>
  <Card title="User-owned web">
    Every user controls their identity, data, and attention — no platform
    intermediaries.
  </Card>
  <Card title="Programmable value">
    The Web3 Score and module economy make contribution directly valuable.
  </Card>
  <Card title="Decentralized infrastructure">
    The browser runs on a network of user-operated nodes, not centralized
    servers.
  </Card>
  <Card title="Open standards by default">
    Every protocol, format, and API is an open standard governed by the
    community.
  </Card>
</CardGrid>

The manifest is the declaration every Orivon package ships: what it is, what
it needs, and what it may do. This draft defines the manifest format precisely.

## Summary

Every package carries an `orivon.toml` manifest declaring identity, version,
dependencies, permissions and lifecycle hooks. The manifest is validated
against a schema and is the single source of truth for what a package may do.

## Purpose

The manifest is the contract between a package author and everyone who runs or
reviews the package. It exists so that capabilities are explicit, reviewable
and machine checkable before any code runs.

## Example

A realistic manifest as defined by this draft:

```toml
[package]
name = "example-app"
version = "0.1.0"
authors = ["alice.orivon"]

[permissions]
allow = ["identity.read", "wallet.sign"]

[hooks]
on_install = "install"
on_activate = "activate"

[dependencies]
"core-utils" = "0.1.0"
```

The exact field names, optionality and defaults are the normative content of
this draft and are subject to review.

## Implementation status

The reference implementation includes a manifest parser and schema validator.
The draft tracks the format at 0.1.0. No conformance suite has been published
yet.

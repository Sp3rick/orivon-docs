Core services are the privileged middle layer of the system. This draft defines
their boundaries, the request pipeline every call travels, and the guarantees
that structure provides.

## Summary

The core layer is a set of isolated services (session, wallet, policy, module,
naming, config) behind a single API. Every privileged operation passes through
the pipeline `authenticate, authorize, validate, execute, emit`. The reference
design is the [Core Architecture](/docs/technical-design/core-architecture)
page.

## Purpose

The core layer exists so that no privileged operation happens by accident. By
routing every call through one audited pipeline, the system guarantees that
identity, policy and input validation are always applied, in a fixed order, in
one place.

## Implementation status

The reference implementation includes the core services with the five stage
pipeline, constructor based dependency injection and per service isolation. The
draft tracks the reference design at 0.1.0. No conformance suite has been
published yet.

## Future work

- Formal verification of the policy core.
- Service federation across devices.
- Deeper audit tracing across the pipeline.

Modules are how the ecosystem extends Orivon. This draft defines how modules
are identified, packaged, loaded, versioned and retired.

## Summary

A module is packaged as an Orivon Module Package (OMP), declared by a manifest,
pinned by a lockfile to content addressed dependencies, and run in a sandboxed
runtime host. The reference design is the
[Module Architecture](/docs/technical-design/module-architecture) page.

## Purpose

Modules are untrusted code with granted capabilities. The module system exists
to make that safe and tractable: verified identity, pinned dependencies,
explicit permissions and a defined lifecycle from registration to uninstall.

The reference implementation includes the module loader with signed load
plans, content addressed dependency pins and lifecycle enforcement. The draft
tracks the reference design at 0.1.0. No conformance suite has been published
yet.

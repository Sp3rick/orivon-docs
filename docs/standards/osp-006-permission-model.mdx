Permissions are how untrusted code gets limited, reviewable access to the
system. This draft defines the capability model, the grant flows, and how
permissions are enforced.

## Summary

Access is capability based with a default deny policy. Grants are requested,
evaluated by the policy broker, and either auto granted, consented or denied.
Every privileged call is checked against the grants at runtime. The reference
design is the [Permission System](/docs/technical-design/permission-system)
page.

## Purpose

The permission model exists so that a module or application can do exactly
what it declared and nothing else. It turns "trust the module" into "trust the
granted capabilities", which is reviewable and revocable.

## Example

The policy API as defined by this draft:

```rust
let decision = policy.check("wallet.sign", scope).await;
match decision {
    Grant::Allowed => sign(),
    Grant::NeedsConsent => present_consent().await,
    Grant::Denied => return Err(PermissionError::Denied),
}
```

The exact API surface and grant types are normative content under review.

## Implementation status

The reference implementation includes the policy broker, scoped grants and
runtime enforcement in the core layer. The draft tracks the design at 0.1.0.
No conformance suite has been published yet.

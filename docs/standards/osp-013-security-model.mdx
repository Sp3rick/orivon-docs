model: the goals, the threat model, and the guarantees every other
specification builds on.

## Summary

The security model defines four goals (protect identity and value, contain
compromise, ensure integrity, keep secrets), the threat model, and the defense
in depth layers that enforce them. The reference design is the
[Security Architecture](/docs/technical-design/security-architecture) page.

## Purpose

A security model must be stated before it can be evaluated. This specification
exists so that every security decision in the ecosystem can be checked against
a written model instead of an implicit one.

## Implementation status

The reference implementation enforces the model through process isolation,
sandboxing and the policy layer. The draft tracks the model at 0.1.0. No
conformance suite has been published yet.

## Future work

- Formal verification of the policy core.
- Memory safe components for high risk parsers.
- Cooperative sandbox verification in CI.

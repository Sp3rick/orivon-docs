The runtime host is the process that executes Orivon modules. This draft
defines its lifecycle, its execution environment, and how it relates to the
core services.

## Summary

The runtime host isolates each module in its own sandboxed process, provides a
WebAssembly execution environment, and brokers all privileged access through
the core services. It is the execution counterpart to the
[Technical Design](/docs/technical-design/runtime-architecture) of the same
name.

## Purpose

Modules run untrusted code on the user's machine. They need an environment that
is fast, sandboxed, and unable to reach keys or the host without authorization.
The runtime host is that environment. Without it, every module would be a
privilege escalation.

## Implementation status

The reference implementation includes a runtime host with process isolation, a
sandboxed WASM environment and lifecycle enforcement. The draft tracks the
current reference design at version 0.1.0. No conformance suite has been
published yet; see [Conformance Testing](/docs/standards/conformance-testing).

## Future work

- Process sharing for identical runtime applications.
- Snapshotting for instant application restore.
- GPU surface integration for runtime rendering.

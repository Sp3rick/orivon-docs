The browser is the surface users see and the place where every other system
meets. This draft defines its process topology, its tab lifecycle and its
navigation model.

## Summary

The browser coordinates a privileged process, per site renderers, runtime
hosts and the core services. Tabs move through a defined lifecycle, navigation
is governed by the navigation controller, and every privileged action is
brokered. The reference design is the
[Browser Architecture](/docs/technical-design/browser-architecture) page.

## Purpose

The browser exists to present untrusted content and applications safely. Its
architecture answers the two structural questions: what runs in which process,
and what happens to a tab over its lifetime.

## Implementation status

The reference implementation includes the browser with per site renderers,
tab state management and the broker model. The draft tracks the reference
design at 0.1.0. No conformance suite has been published yet.

## Future work

- Spare renderer processes for instant tab restoration.
- Tab snapshotting.
- Process sharing where isolation allows.

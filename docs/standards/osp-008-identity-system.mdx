Identity is the root of trust in the ecosystem. This draft defines the identity
model, the DDoc document format, authentication and recovery.

## Summary

An identity is a DDoc based identifier (`did:orivon`), a set of public keys and
services, and a lifecycle from creation to revocation. Authentication is
challenge signature based and sessions are short lived. The reference design is
the [Identity Layer](/docs/technical-design/identity-layer) page.

## Purpose

Everything in the ecosystem anchors to identity: signing, permissions, storage
encryption and value. The identity system exists so that this anchor is
standard, portable and verifiable by anyone.

## Example

A DDoc as defined by this draft:

```json
{
  "id": "did:orivon:z6Mkq...",
  "controllers": ["did:orivon:z6Mkq..."],
  "keys": [
    {"id": "#key-1", "type": "ed25519", "publicKey": "z6Mkq..."}
  ],
  "services": [
    {"id": "#storage", "type": "storage", "endpoint": "..."}
  ]
}
```

The exact DDoc schema, key types and service entries are normative content
under review.

## Implementation status

The reference implementation includes DDoc based identity, challenge
authentication and session management. The draft tracks the design at 0.1.0.
No conformance suite has been published yet.

## Future work

- A `did:orivon` registry and resolution standard.
- Delegation and multi controller identities.
- Cross ecosystem interop via public DDoc work.

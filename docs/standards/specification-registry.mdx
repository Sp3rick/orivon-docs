The registry is the single point of truth for the Orivon specification series.
Every document is listed here with its identifier, title, category, status,
version, last update and summary. The registry is searchable and filterable, so
you can find a specification by identifier, by what it covers, or by where it
stands in the [lifecycle](/docs/standards/specification-lifecycle).

## Using the registry

- **Search** by identifier, title or summary.
- **Filter by status** to see only drafts, accepted or deprecated documents.
- **Filter by category** to narrow to one area of the ecosystem.
- Each row links to the full specification page.

Every specification is also indexed by the site-wide
[search](/docs/technical-design), so typing an OSP identifier anywhere finds it.

<Callout type="warning" title="Read the status">
  A **Draft** entry is a direction, not a promise. Only an **Accepted**
  specification is normative. See [Versioning](/docs/standards/versioning) for
  what each status and version means.
</Callout>

## Categories

Specifications are grouped into categories that map to the ecosystem. A
category is a label for navigation, not a standard itself:

| Category | Covers |
| --- | --- |
| **Runtime** | The runtime host and module execution |
| **Core** | Core services and the request pipeline |
| **Browser** | Browser processes, tabs and navigation |
| **Modules** | The module system and its lifecycle |
| **SDK** | The developer SDK surface |
| **Wallet** | Key storage and signing |
| **Identity** | Identity, DDoc and authentication |
| **DNS** | Decentralized naming |
| **Networking** | Transports and peer communication |
| **Storage** | Content addressing and persistence |
| **Security** | The security model and guarantees |
| **Cryptography** | Cryptographic primitives and formats |
| **Permissions** | Capabilities and consent |
| **Events** | The event and message system |
| **Configuration** | Configuration files and schemas |
| **Package Format** | The package and manifest format |
| **CLI** | Command line tooling |
| **Developer Tools** | Tooling around the SDK |
| **APIs** | Application interfaces |
| **User Experience** | User facing behavior and consent |

Not every category has a published specification yet. Categories without a
document are expected future work, tracked on the [Roadmap](/docs/standards/roadmap).

  Pin by identifier and version, not by title. An identifier like `OSP-006` is
  stable across every version; a title is not.
</Callout>

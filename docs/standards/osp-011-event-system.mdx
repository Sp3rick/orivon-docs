Everything in the system communicates by message. This draft defines the event
system: the message kinds, their schemas and the ordering rules.

## Summary

The event system defines four message kinds (request, response, event,
broadcast), typed schemas for every message, and ordering guarantees per
sender and per service. The reference design is the
[Communication Bus](/docs/technical-design/communication-bus) page.

## Purpose

When components are separate processes, the message surface is the whole
integration surface. The event system exists so that this surface is typed,
versioned and ordered predictably.

## Example

An event as defined by this draft:

```json
{
  "kind": "event",
  "topic": "wallet.signature",
  "payload": {"requestId": 42, "status": "signed"},
  "seq": 7,
  "sender": "orivon.wallet"
}
```

The exact schemas, topic names and sequence rules are normative content under
review.

## Implementation status

The reference implementation includes the broker, typed messages and ordering
guarantees. The draft tracks the design at 0.1.0. No conformance suite has been
published yet.

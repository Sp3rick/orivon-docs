Configuration is how the system is told what to do without being rewritten.
This draft defines the configuration model: scopes, schemas, validation and
delivery.

## Summary

Configuration is organized in scopes (build, system, profile, runtime), every
value is schema validated with a default, and services receive versioned
snapshots of only the configuration they are allowed to see. The reference
design is the [Configuration](/docs/technical-design/configuration) page.

## Purpose

Configuration must be safe to change and safe to read. The model exists so
that invalid values are rejected before they take effect, and so that no
component can read configuration it does not need.

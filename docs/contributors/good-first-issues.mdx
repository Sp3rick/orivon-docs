Good first issues are the doorway into Orivon: tasks that are scoped,
mentored and sized for a first contribution. This page explains how to pick
one, what to expect, and how to make the most of your first experience.

<Callout type="success" title="Designed for your first PR">
  Good first issues are chosen to teach one skill and end in a merged
  contribution. They are not trivial busywork; they are real work with a
  clear path.
</Callout>

## What makes a good first issue

Good first issues share a shape:

<CheckList
  items={[
    'Small and clearly scoped.',
    'Self-contained, with an explicit expected outcome.',
    'Well documented, with pointers to the relevant code.',
    'Reviewable by a single focused change.',
    'Accompanied by a mentor or reviewer willing to guide.',
  ]}
/>

## Where to find them

Issues labeled `good first issue` in the repositories:

| Kind of task | Examples |
| --- | --- |
| Documentation | Broken links, unclear pages, missing examples |
| Code | Small fixes, better errors, test coverage |
| Design | Icons, illustrations, diagram improvements |
| Localization | Translating a page or interface strings |
| Community | Triage help, improving the contribution guides |

## How to pick one

Choose the issue that matches your goals:

<Steps>
  <Step title="Match your skills">
    Pick work you can mostly do with the docs and a little help.
  </Step>
  <Step title="Read the issue">
    Make sure you understand the expected outcome and the pointers.
  </Step>
  <Step title="Claim it">
    Comment on the issue to say you are working on it.
  </Step>
  <Step title="Ask early">
    Ask questions before you go too deep; the mentor is there for that.
  </Step>
</Steps>

<Callout type="info" title="Claim to avoid collisions">
  Saying you are taking an issue prevents two people doing the same work.
  If you find you cannot finish, unclaim it so someone else can.
</Callout>

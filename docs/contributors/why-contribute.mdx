Every contribution to Orivon has a reason behind it. Some contribute for the
mission, some for the learning, and some for the community. This page lays
out the honest case for each, so you can find the reason that is yours.

## The mission

Orivon exists to build a web users own and control: a trustless, user owned
alternative to the platforms that mediate the web today. When you contribute,
you are not just improving software. You are building the infrastructure of
that alternative.

<Callout type="success" title="A contribution is a vote">
  Open standards only stay open if people build them. Each merged change is a
  small step toward a web that is governed by its users instead of its
  intermediaries.
</Callout>

## The learning

Contributing is the fastest way to learn the architecture deeply:

- Reading and writing production code in a demanding codebase.
- Understanding a security first runtime: sandboxing, permissions, identity.
- Learning how large projects organize work, review and release.
- Working with an open standards process, which is how real ecosystems decide.

You leave with knowledge you cannot get from any course, because it comes
from doing the real work.

## The career

Public, attributed work is a portfolio that speaks for itself:

| Benefit | What it means |
| --- | --- |
| Visible track record | Your PRs and reviews are public history |
| Proven skills | Working code, reviewed by others, is proof |
| Network | Maintainers and contributors know your work |
| Growth | Recognition opens doors to roles and grants |

Contributors are also acknowledged through the
[Recognition](/docs/contributors/recognition) program.

## The recognition

Orivon acknowledges contributors publicly and materially:

- Every contributor is listed and credited.
- Significant contributions appear in release notes.
- The rewards program recognizes high impact work.
- Maintainers and leaders are drawn from the contributor base.

See [Recognition](/docs/contributors/recognition) for the details.

## What contribution is worth

Different contributions carry different weight, and every one is valued:

<CardGrid columns={2}>
  <Card title="A bug report">
    A clear report with a repro saves hours and protects users. It is a real
    contribution.
  </Card>
  <Card title="A documentation fix">
    Clearer docs are used by every future reader. Small, high leverage.
  </Card>
  <Card title="A code fix">
    Merged fixes ship to every user and move the platform forward.
  </Card>
  <Card title="A review">
    A good review improves the change and teaches its author.
  </Card>
</CardGrid>

## Contribution and compensation

The DAO and rewards program are designed to sustain contributors:

<Accordion title="Are contributions paid?">
  Some high impact work is rewarded through the DAO and grants process, and
  the details evolve with the [governance](/docs/ecosystem/governance) model.
  Most work is volunteered, which is what keeps the project independent.
</Accordion>

<Accordion title="Who owns my contribution?">
  Contributions are made under the project license, and you retain credit for
  your work. See the [code of conduct](/docs/contributors/code-of-conduct)
  and repository license for specifics.
</Accordion>

## What it takes

Contributing does not require genius or spare time. It requires:

<Steps>
  <Step title="Curiosity">
    A question to answer or a problem to solve.
  </Step>
  <Step title="Patience">
    Reviews take time; good work gets there through iteration.
  </Step>
  <Step title="Consistency">
    Small, steady contributions compound.
  </Step>
</Steps>

<Callout type="info" title="You belong here">
  Every maintainer was once a first timer. The skills you have today are
  enough to make your first contribution, and the community will help with
  the rest. See [Getting Started](/docs/contributors/getting-started).
</Callout>

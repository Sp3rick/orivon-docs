Orivon is for the whole web, which means the whole world. Localization makes
the platform usable in languages beyond English, and it is a contribution
that does not require coding. This page explains how to help.

<Callout type="success" title="Anyone can localize">
  If you speak a language besides English, you are qualified. The tools are
  simple and the community helps with consistency.
</Callout>

## The localization workflow

<Steps>
  <Step title="Choose a language">
    Join an existing language team or propose a new one.
  </Step>
  <Step title="Translate">
    Work on the files assigned to your language.
  </Step>
  <Step title="Review">
    Another native speaker reviews your translation.
  </Step>
  <Step title="Ship">
    The translation merges and reaches users.
  </Step>
</Steps>

## Translation quality

Good translation is more than word substitution:

<CheckList
  items={[
    'Translate meaning, not word order.',
    'Keep technical terms consistent with the glossary.',
    'Preserve the tone: clear, plain, respectful.',
    'Keep code, commands and placeholders untranslated.',
    'Match UI strings exactly where they appear.',
  ]}
/>

<Callout type="warning" title="Do not translate code">
  Code blocks, commands, package names and configuration values stay as they
  are. The prose around them is what translates. Translating a command
  breaks it.
</Callout>

## Glossaries

Each language maintains a glossary for consistency:

| Term | Why it is consistent |
| --- | --- |
| Module | Always the same word |
| Sandbox | One agreed term |
| Permission | One agreed term |

If the glossary does not cover a term, propose an addition with your team
before translating it in many places.

## Starting a new language

To start a new language:

<CheckList
  items={[
    'Check that a team does not already exist for it.',
    'Propose the language in the community discussions.',
    'Find at least one more native speaker to review.',
    'Set up the language directory and start with a few pages.',
    'Grow scope as the team grows.',
  ]}
/>

A language with one translator and no reviewer produces translations no one
checks. Teams need both.

## Getting recognition

Localization is real, credited work:

- Translators are acknowledged in the
  [recognition](/docs/contributors/recognition) program.
- Significant translation appears in release notes.
- Language teams grow into maintainer roles.

<Callout type="info" title="Start small">
  Begin with one page you use yourself. A correct, complete page beats a
  partial translation of ten. Quality spreads from the pages that are done
  well.
</Callout>

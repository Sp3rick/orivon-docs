The community is where contributors meet, ask questions and make decisions.
This page explains the channels we use, how we discuss, and the principles
that keep collaboration productive and kind.

<Callout type="info" title="The tone is up to all of us">
  Tools and processes help, but the quality of a community is decided by its
  members. The [Code of Conduct](/docs/contributors/code-of-conduct) is the
  floor; these guidelines are how we aim higher.
</Callout>

## Communication channels

Each channel has a purpose. Using the right one gets you a faster, better
answer.

| Channel | Purpose |
| --- | --- |
| GitHub issues | Bugs, feature requests, actionable work items |
| GitHub discussions | Questions, ideas, design conversations |
| Chat (Discord) | Fast help, announcements, casual collaboration |
| Mailing list | Long form proposals and announcements |
| Meetups and events | Synchronous collaboration and onboarding |

<Callout type="success" title="Best practice">
  If it is an actionable task, open an issue. If it is a question or idea,
  start a discussion. If it is urgent and informal, use chat. Matching the
  medium to the message keeps every channel healthy.
</Callout>

## Asking questions

Good questions get good answers. When you ask:

<CheckList
  items={[
    'Search first: the answer may already exist in the docs or a discussion.',
    'State what you tried and what happened, not just the symptom.',
    'Include versions, commands and error output.',
    'Ask one focused question at a time.',
    'Follow up when the answer helped, so the thread is useful to others.',
  ]}
/>

See [Issue Guidelines](/docs/contributors/issue-guidelines) for the formal
paths.

## Community etiquette

The small habits that make a community pleasant:

<CheckList
  items={[
    'Thank people for help; it is free and it matters.',
    'Do not ping maintainers for status; updates arrive when ready.',
    'Keep threads on topic; move tangents to a new discussion.',
    'Do not re-open resolved threads without new information.',
    'Respect time zones: replies are asynchronous, not instant.',
  ]}
/>

## Collaboration principles

How we work together on shared work:

<CardGrid columns={2}>
  <Card title="Default to open">
    Prefer public channels over private ones, so others can learn and join.
  </Card>
  <Card title="Decide with the community">
    Significant changes go through discussion and, where relevant, the
    standards process.
  </Card>
  <Card title="Credit generously">
    Acknowledge the authors of ideas and the reviewers of changes.
  </Card>
  <Card title="Disagree constructively">
    Push back on ideas with evidence, and stay open to being wrong.
  </Card>
</CardGrid>

## Conflict resolution

Disagreement is normal in a healthy community. The resolution path:

<Diagram caption="Resolving disagreements, escalating only as needed.">
  <Flow column>
    <DiagramNode accent>Discuss on the thread</DiagramNode>
    <FlowArrowDown />
    <DiagramNode>Ask a maintainer to mediate</DiagramNode>
    <FlowArrowDown />
    <DiagramNode>Escalate to the community team</DiagramNode>
    <FlowArrowDown />
    <DiagramNode dim>Enforce the code of conduct if needed</DiagramNode>
  </Flow>
</Diagram>

Most disagreements are resolved on the thread by people who listen. Escalate
only when the discussion is not moving forward or behavior crosses a line.

## Recognition of contributions

Collaboration includes celebrating the work:

- Merged contributions are acknowledged by reviewers.
- Significant work appears in [release notes](/docs/contributors/recognition).
- The [mentorship](/docs/contributors/mentorship) program pairs newcomers
  with experienced contributors.

<Callout type="success" title="The golden rule">
  Assume good faith, explain your reasoning, and treat every contributor as a
  colleague. Communities built on this rule retain their best people.
</Callout>

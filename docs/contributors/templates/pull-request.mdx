Use this template when opening a pull request. Copy it into your PR
description and fill in every section. See
[Pull Requests](/docs/contributors/pull-requests) for the full process.

```markdown
### Summary
What this change does, in one or two sentences.

### Motivation
Why the change is needed. Reference the issue it resolves.

### Test plan
What you ran and the results, including the relevant test commands.

### Checklist
- [ ] Change is small and focused on one thing.
- [ ] Local checks pass (format, lint, type, tests).
- [ ] New behavior has tests; fixes have regression tests.
- [ ] User-visible changes update the relevant documentation.
- [ ] No secrets or personal data are introduced.
- [ ] No permission or sandbox regressions.
- [ ] Commit messages follow the repository convention.

### Tradeoffs and follow-ups
Anything the reviewer should weigh, and any work that should follow.
```

<Callout type="info" title="Merge-ready from the start">
  A PR that meets the checklist on the first push moves through review fast.
  The reviewer is verifying the change, not fixing the process.
</Callout>

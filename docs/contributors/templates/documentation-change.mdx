Use this template for documentation pull requests. Copy it into your PR
description and fill in every section. See
[Documentation Contributions](/docs/contributors/documentation-contributions)
for the guidance on documentation work.

```markdown
### Summary
The page or content this changes, and what the change improves.

### Motivation
Why the change helps readers. Reference the issue if one exists.

### Verification
- [ ] Ran the dev server and viewed the page.
- [ ] Verified links and code in the changed content.
- [ ] Checked the page answers: what, why, how, mistakes, learn more.

### Checklist
- [ ] Frontmatter is complete and accurate.
- [ ] Follows the [documentation standards](/docs/contributors/documentation-standards).
- [ ] Language is plain, clear and consistent.
- [ ] No secrets or personal data are introduced.
- [ ] The change is small and focused.
```

<Callout type="success" title="Verification matters">
  Run the dev server and look at your page before opening the PR. A
  self-verified documentation change is the fastest kind to merge.
</Callout>
